# Docker

The Docker image is the recommended way to run Headplane. It includes the web
UI, [machine details](/features/machine-details) and the [Browser SSH](/features/ssh) module,
all prebuilt.

## Prerequisites

- Docker with Docker Compose
- Headscale {versions.headscale.minimum} or newer, already running
- A Headplane config file with at least `headscale.url` and
  `server.cookie_secret` set (see [Before you start](/install#before-you-start))

## Installation

Mount your config file and a directory for Headplane's own data, which holds
its database and the Tailscale state for machine details:

```yaml
services:
  headplane:
    image: ghcr.io/tale/headplane:latest
    container_name: headplane
    restart: unless-stopped
    ports:
      - "3000:3000"
    volumes:
      - "./config.yaml:/etc/headplane/config.yaml"
      - "./headplane-data:/var/lib/headplane"
```

If Headscale runs in Docker too, put both containers on the same network and
point `headscale.url` at the container, for example `http://headscale:8080`.

Run `docker compose up -d`, then open `http://localhost:3000/admin`.

## Signing in

Until [SSO](/features/sso) or [proxy authentication](/features/proxy-auth) is
set up, sign in with a Headscale API key, created inside the Headscale
container:

```bash
docker exec headscale headscale apikeys create --expiration 90d
```

See [API keys](/configuration/api-keys) for how keys and sessions work.

## Health checks

The image has a built-in healthcheck, so `docker ps` reports whether Headplane
is up without any extra configuration. It follows Headplane's port and TLS
settings on its own. To change its timing, override it in your compose file:

```yaml
services:
  headplane:
    healthcheck:
      test: ["CMD", "/bin/hp_healthcheck"]
      interval: 30s
      timeout: 5s
      start_period: 5s
      retries: 3
```

## Debugging

The image has no shell. When you need one, switch to the matching `-shell` tag,
such as `ghcr.io/tale/headplane:latest-shell`. It's the same build on Alpine,
with `bash` and `curl`.

## Next steps

At this point Headplane can manage machines, users, auth keys and ACLs. To edit
DNS settings and sign-in restrictions from the UI, set up the
[Docker integration](/configuration/integrations#docker). After that, put
Headplane behind a [reverse proxy](/configuration/reverse-proxy).
