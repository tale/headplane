# Installation

Every installation method ends in the same place: Headplane running next to an
existing Headscale server, serving its UI under `/admin`. Pick the method that
matches how you already run Headscale.

| Method                         | Use it when                                              |
| ------------------------------ | -------------------------------------------------------- |
| [Docker](/install/docker)      | Headscale runs in Docker, or you don't mind running both |
| [Native](/install/native-mode) | Headscale runs directly on the host, often under systemd |
| [Nix/NixOS](/install/nix)      | You manage the machine with NixOS                        |

Docker is the recommended method. It ships everything prebuilt, including the
agent and Browser SSH, and it's the only setup where Headplane can restart
Headscale without a supervisor.

## Before you start

You'll need Headscale {versions.headscale.minimum} or newer, already running.
Headplane reads its settings from a YAML file, `/etc/headplane/config.yaml` by
default. Start from the
[example configuration](https://github.com/tale/headplane/blob/main/config.example.yaml)
and set at least these two fields:

```yaml
headscale:
  # How Headplane reaches Headscale, for example http://headscale:8080 in Docker
  url: "http://headscale.example.com"

server:
  # Exactly 32 characters, for example from `openssl rand -base64 24`
  cookie_secret: "<32 random characters>"
```

Everything else has a default. [Configuration](/configuration) covers the file
in detail, including environment variables and keeping secrets out of it.

## After installing

Once Headplane is up, sign in with a Headscale API key and decide how much it
should manage:

- **Edit DNS and sign-in restrictions** from the UI by giving Headplane access to
  Headscale's config file. See [Integrations](/configuration/integrations).
- **Put it behind a reverse proxy** on the same domain as Headscale. See
  [Reverse proxy](/configuration/reverse-proxy).
- **Let people sign in with their own accounts** through [SSO](/features/sso) or
  [proxy authentication](/features/proxy-auth).
- **Show machine versions and open SSH sessions** from the browser with the
  [agent](/features/agent) and [Browser SSH](/features/ssh).
