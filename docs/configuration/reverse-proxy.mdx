# Reverse proxy

The recommended setup serves both from one domain: Headplane under `/admin`,
Headscale on everything else. Both then share one certificate, and because the
browser sees a single origin, no CORS headers are needed.

Whatever the proxy:

- Route `/admin` to Headplane (port 3000) and everything else to Headscale
  (port 8080).
- Forward WebSocket upgrades to Headscale. Tailscale clients and
  [Browser SSH](/features/ssh) both rely on them.
- Set `server.base_url` in Headplane's config to the public URL, such as
  `https://headscale.example.com`. [SSO](/features/sso) needs it to build its
  callback URL.

Leave `server.cookie_secure` at its default of `true` when the proxy serves
HTTPS. Set it to `false` only when Headplane is reached over plain HTTP, or
sign-in won't stick.

## Caddy

Caddy forwards WebSocket upgrades without extra configuration:

```caddyfile
headscale.example.com {
    # Optional: send visitors at / to Headplane
    redir / /admin/

    handle /admin* {
        reverse_proxy localhost:3000
    }

    handle {
        reverse_proxy localhost:8080
    }
}
```

## nginx

nginx needs the `map` block to forward WebSocket upgrades:

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    '' close;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name headscale.example.com;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
    }

    location = /admin {
        return 301 /admin/;
    }

    location /admin/ {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

certificate setup to the `traefik` service. Traefik forwards WebSocket upgrades

## Separate domains

Headplane and Headscale can also live on different domains, such as
`headplane.example.com` and `headscale.example.com`. Everything works the same
except [Browser SSH](/features/ssh), which connects from the browser straight
to Headscale. Its WebSocket connections aren't subject to CORS, but it first
fetches Headscale's public key with a plain cross-origin request, so
Headscale's responses need an `Access-Control-Allow-Origin` header with
Headplane's origin. In Caddy:

```caddyfile
headscale.example.com {
    reverse_proxy localhost:8080

    header Access-Control-Allow-Origin "https://headplane.example.com"
}
```

In nginx, add `add_header Access-Control-Allow-Origin "https://headplane.example.com" always;`
to Headscale's `location`.

## A different path

To serve Headplane somewhere other than `/admin`, such as `/tools/headplane`,
set `server.base_path` and restart Headplane:

```yaml
server:
  base_path: "/tools/headplane"
```

The path starts with a slash, doesn't end with one, and can't be `/`. Route it
to Headplane in the examples above in place of `/admin`, without stripping it.
Keep the path out of `server.base_url`. With [SSO](/features/sso), register the
callback under the new path. Changing the path signs everyone out, since
sessions are tied to it.

## Serving HTTPS without a proxy

Headplane can terminate TLS itself, which suits a single machine without a
proxy. See [TLS & certificates](/configuration/tls#tls-termination).
